Architecture case study

Running a premium linen company with no humans in daily operations

This is the architecture for Halden Home, a fictional D2C brand selling premium bedding and towels. Yves Delorme is one of its suppliers; that relationship is hypothetical. AI agents run every day-to-day decision: selling, forecasting, buying, pricing, marketing, service, finance and exceptions. Physical warehousing and last-mile delivery are outsourced to a 3PL.

The design in six sentences
  • Agents propose, deterministic systems dispose. No agent writes to a database or calls a vendor directly. Every side effect is a typed Action Proposal sent to an Action Gateway. The gateway enforces policy, limits, idempotency and audit.
  • Each job gets the cheapest tool that can do it reliably. Deterministic code handles money and stock. ML handles forecasting and elasticity. Rules and policy handle limits. LLMs handle language, ambiguity and messy supplier documents.
  • Events are the nervous system and Postgres is the memory. An append-only Ops Ledger, a transactional outbox and a message bus keep shared state consistent. Durable workflows (Temporal) run the long processes, such as a purchase order that takes 21 days.
  • A thin in-house harness wraps every agent. It handles context assembly, a bounded tool loop, validation, a maker-checker verifier, memory hygiene and tracing. The model decides intent. The harness decides whether that intent is valid.
  • Autonomy is tiered and budgeted. Each action carries a risk tier (T0-T3) and a spend, price or refund envelope. Anomaly detection can quarantine one agent, and kill switches stop a whole domain, without stopping the business.
  • We buy commodity systems and build the brain. Shopify, Stripe, the 3PL, accounting, EDI and marketing tools are bought. The agent runtime, Action Gateway, Ops Ledger, planning models and supplier adapters are built.

Architectural principles

1 · LLMs never own the truth

Quantities, prices, balances and stock levels are always computed by deterministic code or ML and read through tools. An LLM may explain a number or choose between options. It never invents one.

2 · Single writer per aggregate

Each domain service owns its tables. Agents act only through the Action Gateway. Two agents can never race on the same purchase order or price.

3 · Fail loud, never silently "fix"

If an agent's output fails validation, the error goes back to the agent so it can self-correct, or the task escalates. The harness never quietly substitutes its own guess, because a hidden fallback also hides the defect.

4 · Every action is replay-safe

Idempotency keys, durable workflows and the outbox pattern mean a retry can never produce a second PO, refund or charge.

5 · Least privilege per agent

Each agent has its own workload identity, scoped tools and short-lived tokens. Secrets never enter a prompt. Credentials are attached by the gateway at call time.

6 · Humans set the envelope, not the decisions

Owners set budgets, margin floors and policies. A human sees only true exceptions, targeted at under 1% of decisions. "No humans in normal operations" is a measured SLO, not a slogan.

Vocabulary used throughout

TermMeaning
AgentA stateless reasoning worker (LLM, ML or rules) with a declared mandate, tool allow-list and identity. It is invoked by events or workflows.
HarnessThe deterministic runtime around a model. It assembles context, runs the bounded tool loop, validates outputs, persists memory and emits traces.
Action ProposalA typed, signed request for a side effect, e.g. CreatePurchaseOrder. Agents emit it; only the Action Gateway executes it.
Action GatewayThe one choke point for side effects. It checks policy, limits, idempotency, validation, tiered approval and audit.
Ops LedgerThe operational system of record, on Postgres: inventory positions, POs, prices, proposals and an append-only event log.
Risk tier (T0-T3)T0 auto-execute · T1 auto + post-hoc sampling · T2 requires verifier agent / panel · T3 requires human exception review.
EnvelopeThe owner-approved limits an agent works inside: spend per day, maximum discount, refund ceiling, and so on.
