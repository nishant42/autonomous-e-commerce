05 · Agent orchestration

Choreography between domains, orchestration within them

Domains react to each other's events (choreography), which keeps them decoupled. Inside a domain, any process that must finish, such as a PO, a refund or a month-end close, runs as a durable workflow (orchestration). Agents are invoked as workflow activities, so retries, timeouts and history come for free.

Rules of the road
  • Agents do not chat with each other in free text. They communicate through typed events, typed commands and a shared case record.
  • Every long-running process has exactly one workflow instance per business key (e.g. reorder:{supplier}:{sku}), which prevents duplicate work by construction.
  • LLM "decides what next" only inside one agent's bounded tool loop. The business process sequence is code.

Orchestration patterns in use

1 · Router → specialist sub-agents

A supervisor classifies the input and routes it to a specialist using a closed routing table. Example: an inbound supplier email is classified as acknowledgement, delay, price change, invoice or other, then sent to the matching handler. The router returns strict JSON. If a specialist fails, the router returns a defined error payload, never free text.

2 · Maker → Checker

One agent produces and an independent verifier checks: different prompt, often a different model, and read-only tools. Used for supplier document extraction, customer replies, creative and price changes. A pattern from production document pipelines: extractor → mapper → verifier.

3 · Panel + synthesis (T2 decisions)

For high-stakes, judgement-heavy actions such as a large PO, a deep markdown or a new supplier, 3-4 personas assess a frozen decision pack in parallel: Demand Planner, CFO, Risk Officer, Brand. A synthesiser records the consensus level. A split verdict escalates the decision.

4 · Saga with compensation

Multi-system changes, such as cancelling an order after 3PL release, run as sagas. Each step has a compensating action: recall from 3PL, then void the label, then refund. Temporal guarantees the compensations run even after crashes.

5 · Human signal with safe default

A T3 step pauses the workflow and pages an owner. If there is no answer by the deadline, the workflow takes the pre-declared safe default, e.g. place the P50 quantity instead of the P90, or keep the current price. This means autonomy never depends on a human being awake.

6 · Blackboard case record

Cross-domain situations, such as a demand spike, get a case row that every participating agent appends findings to: planner, procurement, pricing, marketing. It is typed, append-only and linked by correlationid, which gives shared context without agent-to-agent chat.

Preventing runaway agent interactions

RiskControl
Event storms / infinite loops (A triggers B triggers A)A causation chain depth limit (e.g. 12) enforced by the bus consumer library. Per-agent invocation rate limits.
Oscillation, e.g. pricing and marketing fighting (raise price → cut ads → lower price → raise ads)Hysteresis bands, minimum dwell time per SKU (price changes at most 2 per week), and the Sentinel's flapping detector, which freezes the SKU and opens a case.
Duplicate work on the same business keyTemporal workflow ID uniqueness (reorder:sup_yd:SKU) and idempotency keys at the gateway.
Cost blow-ups in the tool loopMaximum rounds (8), wall-clock timeout (180s), token budget per task and per agent per day, all enforced by the harness and AI gateway.
Stale decisions (acting on old state)Proposals carry the snapshot's as_of. The gateway rejects them if the aggregate version has moved (optimistic concurrency) and the workflow re-plans.
