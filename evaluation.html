Deep dive G · Evaluation and observability

Agents ship like code: tested, staged, measured

An agent is a bundle of prompt, tools, model and policy, versioned together. No bundle reaches production without passing offline evaluation, shadow mode and canary. In production, every decision is traceable, and a daily sample is re-judged.

Where the golden sets come from

Real, redacted production cases: every incident, every Auditor finding, every verifier rejection and every T3 escalation becomes a labelled test case. The suite grows with the company's own edge cases. Using real traces also avoids the trap of evaluating on synthetic, easy examples.

Observability

One trace per business flow

OpenTelemetry context propagates from the webhook through the bus, workflow, harness, model call, tool call, gateway, adapter and vendor. The correlationid links it to the case, so "why did this happen?" is a single trace view.

LLM-specific spans

Model, deployment, prompt version, input and output tokens, cached tokens, latency, tool calls and finish reason. Content is stored with PII redaction and retention limits.
