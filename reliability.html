Deep dive F · Reliability and failure recovery

Everything fails; nothing is lost or done twice

Reliability rests on three guarantees. At-least-once delivery of events, plus idempotent handling, gives effectively-once outcomes. Durable workflows resume after crashes. Every automated behaviour has a degraded mode that keeps the shop trading.

Retry policy by layer

adapter.http:     { attempts: 5, backoff: "exp(1s..60s)+jitter", retryOn: [429, 500, 502, 503, 504, "ETIMEDOUT"] }
temporal.activity:{ attempts: 6, initialInterval: "5s", maxInterval: "10m", nonRetryable: ["ValidationError", "PolicyDenied", "Halted"] }
bus.consumer:     { maxDeliveryCount: 10, then: "DLQ", dedupe: "event.id (7-day window)" }
model.call:       { attempts: 2, onFail: "failover deployment → alt vendor", respect: "shared task deadline" }

Validation errors, policy denials and halts are never retried, because retrying a wrong answer only makes it more expensive.

Degraded modes (what "off" looks like)

Component down or quarantinedThe business keeps running because…
All LLMsOrders, allocation, fulfilment, reconciliation and T0 rules keep running on deterministic paths. Customer care switches to acknowledgement macros with an extended SLA. Supplier inbound email queues.
Pricing agentPrices freeze at the last known good price book. Scheduled promotions still run (pre-approved).
ForecastingThe planner uses the last published forecast with widened safety stock (×1.2).
Marketing agentsAd budgets hold at the current daily level; lifecycle flows continue (pre-built in Klaviyo).
Action GatewayNo side effects anywhere (fail closed). Shopify keeps selling on current state. This is the only component whose outage pauses autonomy, so it is multi-instance and multi-region.
TemporalWorkflows pause and resume exactly where they were. Events buffer in Service Bus.

Recovery and replay

Replay events

Consumers are idempotent and projections are rebuildable from the append-only log, so a buggy projection is fixed by deploying the fix and replaying from an offset.

Replay decisions

Every proposal stores its as_of snapshot and agent version. A decision can be re-run on a new agent version and diffed. This is the basis of shadow evaluation.

Undo actions

Each action type declares its compensation: price change → previous price; PO → cancel before ship or amend; ad budget → previous budget. Runbooks can undo "all actions by agent X since time T".
